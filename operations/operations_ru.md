# Эксплуатация

## Метрики Prometheus

- Нода экспортирует метрики на `cache_stat_port` (по умолчанию 8080), путь `/metrics`.
- Готовый дашборд Grafana: [../dashboards/dashboard.json](../dashboards/dashboard.json).
- Compose-пример поднимает Prometheus + Grafana вместе с кластером:
  [../cluster-compose](../cluster-compose).

Что смотреть в первую очередь:

| Метрика | О чём говорит |
|---|---|
| латентности операций (avg/p99 по операциям) | деградация hot path |
| размер кэша / число ключей | рост данных, давление на память |
| счётчики снапшотов | частота и длительность фоновых сбросов |
| ошибки по операциям | проблемы клиентов/типов |
| статус лицензии | печатается в потоке статистики stdout |

## Снапшоты

- Два триггера, оба настраиваются: по времени (`interval`, по умолчанию 300 с) и по числу
  изменений в партиции (`change_threshold`, по умолчанию 1000).
- Снапшоты фоновые — не влияют на hot path запросов.
- Файлы пишутся в `storage_directory`; при рестарте нода восстанавливает данные из них.
- Проверка: записать ключ, перезапустить контейнер, прочитать — ключ на месте.

## Кластерная эксплуатация

- Добавление ноды — один вызов координаторского API (автоматизируется по HTTP).
- Замена ноды «горячая»: данные копируются внутри кластера.
- Stability window 30–120 с поглощает короткие рестарты без ложных миграций — p99
  не дёргается при деплоях.
- Кластер из трёх нод поднимается меньше чем за минуту.

## Лицензии

- Без файла лицензии действуют community-лимиты: до 3 нод, 1024 партиции, 2 рабочих
  потока на ноду.
- Лицензия — Ed25519-подписанный YAML, привязанный к fingerprint конфигурации кластера;
  проверяется при старте, лицензионный сервер не нужен.
- После истечения — 30-дневный soft-период с теми же лимитами, затем возврат к
  community-лимитам. Без внезапных остановок.
- Подробности формата: `doc/licensing.md` в репозитории сервера.
