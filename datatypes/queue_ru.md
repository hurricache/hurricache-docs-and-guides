# FIFO queue

Очередь «первым пришёл — первым ушёл» с атомарным pop. Основной сценарий —
распределение задач между конкурентными воркерами: элемент достаётся ровно одному
клиенту.

Применение: очереди заказов/задач, балансировка работы между воркерами, буферы событий.

## Java API

| Метод | Что делает | Применение |
|---|---|---|
| `createQueue(key, values, ttl?)` → `KeyHintData` | Создать очередь с начальным содержимым | |
| `pushTail(key, values)` → `Integer` | Поставить в хвост | Постановка задачи |
| `popHead(key)` → `Variant` | Атомарно забрать из головы | Назначение задачи воркеру: один элемент — один получатель |
| `peekHead(key)` / `peekTail(key)` → `Variant` | Прочитать без удаления | Инспекция очереди |
| `deleteHead(count)` / `deleteTail(count)` → `Integer` | Удалить N с конца | Очистка/обрезка |
| `getSize(key)` → `Integer` | Глубина очереди | Мониторинг лага |

## Замечания

- Атомарность `popHead` устраняет гонки: никаких SET NX EX-паттернов для выдачи задач.
- Для надёжной доставки (at-least-once) комбинируйте с локом или подтверждением на
  прикладном уровне: pop удаляет элемент сразу.
- TTL назначается на контейнер целиком.
