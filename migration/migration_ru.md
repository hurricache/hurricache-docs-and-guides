# Миграция с Redis

Пошаговый путь от работающего Redis к HurriCache без остановки сервиса.

## Шаг 0. Проверить покрытие команд

Сверьте ваш набор команд с таблицей покрытия: [../redis-mapping](../redis-mapping/README.md).
Строки, ключи/TTL, хэши, списки, множества и sorted sets покрыты; pub/sub — в roadmap.

## Шаг 1. Поднять HurriCache рядом (нулевые изменения кода)

```bash
docker run -d --name hurricache-dev \
  -p 127.0.0.1:50000:50000 -p 127.0.0.1:6379:6379 \
  alexaborisov/fastcache-standalone-noavx512:latest
```

RESP-коннектор слушает 6379 — направьте на него существующий Redis-клиент
(тот же host/port, тот же протокол).

## Шаг 2. Снять baseline

```bash
redis-benchmark -p 6379 -t set,get -r 1000000 -n 1000000 -c 100 -d 512
```

Сравните с вашим Redis. Ожидаемые цифры — в таблице производительности на сайте.

## Шаг 3. Перевести горячие пути на gRPC API

По таблице маппинга замените операции на типизированные вызовы:

- `SET NX`/оптимистичные сценарии → `create` + `compareAndSet` (без WATCH-циклов и Lua);
- счётчики → `add`/`sub`;
- hash → `createMap`/`getMap`/`addInContainer`;
- sorted set + hash пары → `OrderedMap` (вес и payload вместе, один TTL).

## Шаг 4. Кластер

- Простые Redis-клиенты продолжают работать через **relay**: любая нода принимает любые
  команды и сама ретранслирует владельцу (+4–5 мс).
- Кластерные клиенты (JedisCluster) получают `MOVED <slot> <ip:port>` с точным адресом
  владельца. Слот = `hash(key) % partitions`; хэш не CRC16, `{hash-tags}` не
  поддерживаются.
- Продакшн: smart-клиент — роутинг на владельца без лишних хопов, прозрачный retry на
  реплику. Прикладной код при переходе standalone → кластер не меняется.

## Шаг 5. Выключение Redis

Когда весь трафик ушёл на HurriCache (RESP или gRPC) и метрики стабильны — Redis можно
выводить из эксплуатации. Данные HurriCache держатся в памяти + снапшотах
(`storage_directory`).

## Типичные грабли

- **Строки-числа**: Redis хранит всё строками, HurriCache — типизировано. После `INCR`
  значение — int64; читайте как число, а не строку.
- **create vs update**: `create` на существующем ключе — ошибка (`ALREADY_EXISTS`),
  а не тихая перезапись. Upsert — это `update`.
- **TTL**: в нативном API TTL в миллисекундах (в Redis EX — секунды) — не перепутайте.
