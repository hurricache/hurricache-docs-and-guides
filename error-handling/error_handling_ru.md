# Обработка ошибок

Java-клиент возвращает `CompletableFuture`; ошибки сервера приезжают как
`ExecutionException` с причиной `io.grpc.StatusRuntimeException`. Код ошибки —
`status.getCode()`.

## Коды ошибок (реальные, из сервера)

| gRPC код | Когда | Что делать |
|---|---|---|
| `NOT_FOUND` | Ключа нет; контейнер пуст для pop-операции | Это штатный «cache miss», не сбой |
| `ALREADY_EXISTS` | `create` на существующем ключе | Использовать `update`/`replace`, или это ожидаемый исход проверки «существует ли» |
| `INVALID_ARGUMENT` | Битый запрос: не читается ключ/тип, неверные параметры | Ошибка клиента — не ретраить без изменений |
| `OUT_OF_RANGE` | Переполнение атомики (int64) или индекс/диапазон вне контейнера | Проверить границы; переполнение не меняет значение |
| `PERMISSION_DENIED` | Объект залочен другим владельцем | Ждать/отпустить лок; чужой лок не снять |
| `FAILED_PRECONDITION` | Кластер: ключ не на этой ноде. В trailing metadata `x-fastcache-route` — адрес владельца | Smart-клиент обрабатывает сам; standalone-клиенту — переподключиться по адресу из метадаты |
| `UNAVAILABLE` / `DEADLINE_EXCEEDED` | Сеть/нода недоступна, таймаут | Ретрай с backoff; smart-клиент ретраит на реплику сам |

## «Нет ключа» ≠ «пустой контейнер»

- `get` по несуществующему ключу → `NOT_FOUND`.
- `getMap`/`getList` по существующему пустому контейнеру → пустая коллекция, статус OK.

Клиент может отличать «промах кэша» от «данных нет по смыслу».

## Паттерн: корректный перехват

```java
try {
    Variant v = cache.get("key").get();
} catch (ExecutionException e) {
    if (e.getCause() instanceof StatusRuntimeException sre) {
        switch (sre.getStatus().getCode()) {
            case NOT_FOUND -> { /* cache miss — штатно */ }
            case PERMISSION_DENIED -> { /* залочено другим владельцем */ }
            default -> throw sre;
        }
    }
}
```

## Ретраи

- `UNAVAILABLE`/`DEADLINE_EXCEEDED` — ретраить с экспоненциальным backoff, идемпотентные
  чтения безопасны всегда.
- Пишущие операции (`create`, `pop`, атомики) не идемпотентны — ретрай только если
  точно известно, что вызов не дошёл (например, ошибка до отправки).
- Кластерный smart-клиент сам роутит на владельца и ретраит на реплику при сбое ноды.
